## Phase 1: Discovery (Website)

- **What does this tool do?** Gives local dev servers stable HTTPS domains (e.g. `https://myapp.localhost`) via a local daemon — no ports in URLs, no hosts-file edits, no browser cert warnings.
- **What's the promise?** "One command and you're there": `antra run --domain myapp.localhost -- pnpm dev`, then open a real URL. No cloud, no accounts, no telemetry. Rust, local-only.
- **Does the website make you want to try it?** Yes. Problem/solution framing, comparison table, architecture diagram, `antra.toml` example, one-line install plus brew alternative.
- **What's confusing or unclear — much improved:**
  - ✅ FIXED: site now states up front that clean URLs need `sudo antra proxy start` once for 443/80, and that without sudo Antra serves `https://myapp.localhost:8443` automatically. The "No ports" row carries the same caveat inline.
  - ✅ FIXED: version pin documented (`ANTRA_VERSION=v0.2.7`), and the comparison table now discloses `.test` & Safari (`hosts sync`) hosts behavior.
  - ✅ FIXED: trust story now says "no sudo needed (macOS uses your login keychain)".
  - Remaining nit: the hero still says "No ports. No /etc/hosts. No certificate warnings" unconditionally — the caveats live one scroll below. Acceptable, but a `*` footnote marker on the hero would be fully honest.
- **Questions before installing:** Is `curl | bash` safe? Yes — script detects OS/arch, verifies sha256, falls back to `~/.local/bin`, and in non-interactive mode now skips CA install with a hint instead of attempting it (see Phase 2).

## Phase 2: Installation

- **Piped install (as a stranger would), 3 runs:** `curl -fsSL https://antra.iifelse.com/install.sh | bash` → downloads `antra-aarch64-apple-darwin` (v0.2.7), checksum verified, `✓ Installed to ~/.local/bin/antra`, `✓ antra 0.2.7 is ready!`. All three runs clean.
- **✅ FIXED — installer `installed_path` stdout pollution (prior #1):** `ok "Installed to …"` now goes to stderr, `✓ antra 0.2.7 is ready!` prints correctly, no `No such file or directory` on the trust step.
- **✅ FIXED — non-interactive trust behavior (prior):** piped run now prints `Non-interactive mode — skipping CA install. Run 'antra trust --user-level' later.` No sudo attempt, no auto-install without consent. Correct.
- **Minor nit (cosmetic):** the graceful skip is preceded by a leaked `bash: line 243: /dev/tty: Device not configured`. The script already handles the failure — it should just silence stderr on the `/dev/tty` probe (`[ -e /dev/tty ] 2>/dev/null` doesn't suppress the `read … < /dev/tty` error). One-character-class fix.
- **Version pin (NEW, works):** `ANTRA_VERSION=0.2.6 … | bash` → `Pinned version: v0.2.6`, installed 0.2.6; unpinned reinstall → `Latest version: v0.2.7`. Teams/CI story delivers as advertised on the site.
- **Safe-to-run feel:** yes — detection, checksum, PATH warning, consent-respecting trust. 9/10, minus the cosmetic tty line.

## Issues Found (ranked)

1. **`/dev/tty` stderr leak in installer (NEW, cosmetic)** — piped run prints `bash: line 243: /dev/tty: Device not configured` before the graceful non-interactive skip. The handling is correct; just silence the probe. Fix: `read -r response < /dev/tty 2>/dev/null`.
2. **Untrimmed child traceback on occupied port (carried over, micro)** — `run` with a busy backend still dumps the raw Python traceback; the new tip + exit-1 + route cleanup make it actionable, so this is polish, not a bug. Optional: collapse child stderr behind `--verbose`.
3. **Hero "No ports…" line unconditional (carried over, micro)** — caveats are now inline one scroll below and in the comparison table; a `*` footnote marker would close the loop.
4. **All five 0.2.4 issues — FIXED** ✅✅✅✅✅ (installer capture, run replace-guard, invalid-domain validation, proxy restore message, doctor error/warning labels).
5. **Prior holds** ✅ (`open` fallback URL, alias persistence, `add` single output, `prune` wording, run exit code, arch mapping, 502/503 pages).
