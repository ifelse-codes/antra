# Antra UX Test — 2026-09-05

## Phase 1: Discovery (Website)

- **What does this tool do?** A local dev proxy that gives your apps stable HTTPS domains (like `myapp.localhost`) without ports, hosts file edits, or cert warnings.
- **What's the promise?** "One command" to get a real HTTPS URL for local dev. No config headaches.
- **Does the website make you want to try it?** Yes. The problem statement resonates (localhost:5173 is annoying), and the comparison table clearly shows advantages over alternatives.
- **Confusing/unclear:** Nothing immediately confusing. Architecture diagram is clear and helpful.
- **Questions before installing:** What permissions does it need? Is the curl one-liner safe?

## Phase 2: Installation

- **How smooth was the install?** Antra was already installed (`antra 0.1.0`). The install script URL on the website (`https://antra.iifelse.com/install.sh`) returns **HTML instead of a shell script** — broken link. The actual script lives at `https://raw.githubusercontent.com/ifelse-codes/antra/main/install.sh`.
- **Did you feel confident it was safe to run?** N/A — already installed. The install script itself looks clean (checksum verification, local-only CA).
- **Any unnecessary/confusing steps?** The broken install URL is a blocker for new users.
- **Additional issue found:** The install script tries `antra trust --yes` but this flag doesn't exist. The `trust` command only supports `--status` and `--remove`.

## Phase 3: First Run

- **`--help` output:** Clear, concise. Lists all 9 commands. Enough to get started.
- **`doctor` output:** Uses ✓/✗/⚠ symbols. Tells you exactly what's wrong and how to fix it. Very good.
- **Could you figure out next steps?** Yes — `antra trust` then `antra proxy start` is obvious.

## Phase 4: Core Usage

- **`antra alias`:** Worked first try. Clear output with domain → port mapping.
- **`antra list`:** Clean table format. Shows domain, port, PID, uptime.
- **`antra run --domain ... --port ... -- command`:** Worked with explicit `--port`. Without `--port`, it auto-detects (picked a random port 51849 for a server on 9090 — confusing mismatch).
- **HTTPS access:** Could not test — daemon couldn't bind to ports 443/80 (already in use by other processes). Had to use alternative ports (8443/8080).
- **`antra proxy status`:** Shows PID, uptime, route count, socket path.
- **Output feel:** Clear and well-formatted. Good use of symbols and colors.

### Issue: `antra run` without `--port` auto-detection is unreliable

When running `antra run --domain myapp.localhost -- python3 -m http.server 9090`, antra registered the route as `127.0.0.1:51849` instead of `9090`. The user must pass `--port` explicitly or the proxy points to the wrong port. The help text says "auto-detected if omitted" but it doesn't actually detect the port from the command.

### Issue: Ports 443/80 often unavailable

On macOS, ports 443 and 80 are frequently used by other services (AirPlay, etc.). The daemon fails to start on these ports without a clear error message. Users need to know to use `--port 8443 --http-port 8080`.

## Phase 5: Error Paths

| Test | Result |
|------|--------|
| Port already in use | OS-level error — clear enough |
| Domain with no route | **TLS handshake fails** with `tlsv1 alert access denied`. No clear "no route found" error. **Confusing.** |
| `proxy stop` when not running | Clear message: "Daemon is not running" ✓ |
| `antra clean` | Prompts for confirmation, removes everything cleanly ✓ |
| `antra remove` | Works, shows before/after route list ✓ |

### Issue: No route returns TLS error instead of a helpful message

Accessing `https://nonexistent.localhost` when the daemon has no matching route returns a TLS error (`tlsv1 alert access denied`). There's no clear "no route found" or 502 error. This is confusing — users won't know if their app is working or if something else is being served.
