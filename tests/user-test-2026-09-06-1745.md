### Stale-trust false green (NEW follow-up, medium)

Repro: at session start, `doctor` reported `✓ CA trusted via login keychain` — yet `curl https://myapp.localhost:8443/` (SecureTransport, keychain-aware) failed with `SSL certificate problem: unable to get local issuer certificate`. The CA file dated from an earlier run than the keychain entry (CA regenerated at some point; keychain held the *old* CA). After re-running `antra trust --user-level`, curl reported `SSL certificate verify ok`.
- `doctor`'s trust check is presence-based (cert with subject in keychain), not verification-based, so a regenerated CA yields a false green. Suggest: verify the actual chain (e.g. verify a fresh leaf against the keychain CA) or compare keychain CA fingerprint with `ca.pem`.
- Related nit: re-running `trust` appended a **duplicate** "Antra Local CA" entry in trust settings (now 2 identical entries) instead of replacing. `trust` should be idempotent.

### Alias persistence (NEW observation, medium-low)

`alias` routes do **not** survive daemon restart (verified: `alias` → `proxy stop` → `proxy start` → `list` shows `(No active routes)`). The registry is in-memory only. For something named a "*static* domain alias", a stranger expects it to persist like a hosts entry. Suggest: persist aliases to disk, or have `proxy stop` warn "N route(s) will be removed".

## Issues Found (ranked)

2. **Stale-trust false green (NEW, medium)** — `doctor`/`trust --status` check keychain *presence*, not chain validity. After CA regeneration they report trusted while TLS clients fail. Verify the chain (or fingerprint `ca.pem` vs keychain) instead.
3. **`trust` not idempotent (NEW, low)** — re-running adds a duplicate "Antra Local CA" trust-settings entry instead of replacing.
4. **Aliases don't survive daemon restart (NEW, medium-low)** — in-memory-only route table wipes "static" aliases on `proxy stop`. Persist aliases or warn on stop.
5. **`doctor` "N error(s), N warning(s)" count mismatch (NEW, trivial)** — lists only `⚠` warnings while claiming errors too.
6. **`add` double output (NEW, trivial)** — prints both the alias-style block and a redundant `✓ Added route` line.
7. **`prune` PID-less line worries needlessly (NEW, trivial)** — `→ X (no PID recorded)` for alias routes reads as a problem before concluding "All alive".
