## Phase 1: Discovery (Website)

- **What does this tool do?** Gives local dev servers stable HTTPS domains (e.g. `https://myapp.localhost`) via a local daemon — no ports in URLs, no hosts-file edits, no browser cert warnings.
- **What's the promise?** "One command and you're there": `antra run --domain myapp.localhost -- pnpm dev`, then open a real URL. No cloud, no accounts, no telemetry. Rust, local-only.
- **Does the website make you want to try it?** Yes. Problem/solution framing ("Local development still looks like 2009"), comparison table vs localhost:port / mkcert+Caddy / ngrok, architecture diagram, and `antra.toml` example are persuasive. Install is one curl line plus a brew alternative.
- **What's confusing or unclear:**
  - Comparison-table row "Hosts file edits: Only for .test" is still cryptic — implies `.localhost` never needs hosts edits, and there is an `antra hosts sync` command (for Safari) undiscoverable from the site. No change since last run.
  - Still no mention that ports 443/80 need sudo, or that fallback ports change the URL you visit (`:8443`). The "No ports" promise reads as unconditional.
  - No version pin in the install line (follows `latest`) — fine for trial, worth knowing for teams. This run demonstrated the consequence: a fresh install today yields 0.2.5, not 0.2.4.
- **Questions before installing:** Is `curl | bash` safe? Mostly yes — script detects OS/arch, verifies sha256, falls back to `~/.local/bin`, asks before trusting CA in TTY mode. (This run reproduced a real installer bug in that flow — see Phase 2.)

## Phase 2: Installation

- **Fetch check:** `curl -fsSL https://antra.iifelse.com/install.sh` serves the installer; `releases/latest` redirects to `v0.2.5`; `v0.2.5` sha256 file fetches correctly. Displayed arch mapping (`darwin-aarch64` → `antra-aarch64-apple-darwin`) is correct.
- **Full installer re-run (as a stranger would, stdin closed to simulate pipe):** downloaded 0.2.5, checksum verified, upgraded `~/.local/bin/antra` 0.2.4 → 0.2.5 (binary timestamp + `--version` confirm). Happy path works.
- **STILL BROKEN — installer stdout pollution breaks `installed_path` (medium, carried over from 0.2.4):** `install_binary()` prints status via `ok "Installed to …"` to **stdout**, and the caller captures with `installed_path="$(install_binary …)"`. Live `install.sh` fetched this run still contains the bug (verified by reading the downloaded script: `ok "Installed to ${dest}"` on stdout + `echo "$dest"`). Observed consequence in this run, identical to last:
  - trust step logged `line 230: ✓ Installed to /Users/.../.local/bin/antra /Users/suman/.local/bin/antra: No such file or directory`,
  - CA auto-install then failed (`You can run 'antra trust' later`). The binary itself was correctly copied, so the damage is confusing output + skipped trust, not a broken install. Fix (unchanged): print status to stderr (`ok … >&2`) and echo only the path to stdout.
- **Non-interactive trust behavior (carried over):** with no `/dev/tty`, the script prints `/dev/tty: Device not configured`, then auto-attempts CA install (which needs sudo and fails in this env). Auto-installing a trust change without an explicit yes in a non-interactive context is questionable; safer to skip with a "run `antra trust` later" hint (the `run` command already uses exactly that pattern — see Phase 4).
- **Safe-to-run feel:** mostly yes — platform detection, checksum verification, PATH warning, asks before trusting in TTY mode. Point off for the non-TTY auto-trust attempt and the garbled path bug.

## Issues Found (ranked)

1. **Installer `installed_path` stdout pollution (carried over, medium)** — `install_binary()` prints `ok "Installed to …"` to stdout; `installed_path="$(install_binary …)"` captures it plus the path. Reproduced verbatim on the live v0.2.5 installer. Fix: `ok … >&2`, echo only `$dest` to stdout.
2. **Installer non-TTY auto-trust attempt (carried over, low-medium)** — piped with no `/dev/tty`, prints `/dev/tty: Device not configured`, then auto-attempts a sudo CA install that fails. Safer to skip with a "run `antra trust` later" hint (the `run` command already does this).
3. **`run` occupied-port traceback noise (residual nit, low)** — friendly tip footer + cleanup now present; only the raw backend traceback above it remains. Consider collapsing backend output behind `--verbose` or framing it as "backend said:".
4. **`proxy start` stale no-routes message (was #4) — FIXED** ✅ Now `✓ Restored N route(s)` with list.
5. **`run` silent duplicate-domain clobber (was #2) — FIXED** ✅ Now `alias`-style replace warning.
6. **Invalid domain sudo suggestion (was #3) — FIXED** ✅ Now immediate `Invalid domain … must not contain spaces`, exit 1.
7. **`doctor` error/warning count mismatch (was #5) — FIXED** ✅ Stopped state uses `✗` + "3 error(s)"; running state uses `⚠` + "2 warning(s)".
8. **Site still silent on sudo/443 + Safari/hosts caveats** — carried over, docs-level.
9. **`proxy stop`-again glyph/exit mismatch (`✗` + exit 0)** — trivial, acceptable as idempotent-OK.
