## Phase 1: Discovery (Website)

Fetched `https://antra.iifelse.com` as a stranger.

- **What does this tool do?** A local dev proxy: run your app once, visit it at a
  stable `https://myapp.localhost` URL instead of `localhost:5173`.
- **What's the promise?** "One command. Real HTTPS. No ports, no `/etc/hosts`,
  no certificate warnings."
- **Does the website make you want to try it?** Yes. Problem grid ("What you got"
  vs "What you wanted") resonates; comparison table vs `localhost:port` /
  mkcert+Caddy / ngrok is honest (admits ngrok wins for sharing); terminal
  example shows exact expected output.
- **Confusing/unclear:** Nothing structural. Minor: the page never mentions that
  privileged ports 443/80 need sudo on macOS, nor what happens without it
  (fallback ports). A stranger on a Mac will hit that within 60 seconds.
- **Questions before installing:** Is the curl pipe safe? (No checksum mention on
  page.) Will it touch my trust store / hosts file without asking?

## Phase 3: First Run

- **`--help`:** One-line description + 13 command groups
  (`run dev add list doctor trust proxy clean alias open remove prune hosts service`
  + `help`). Enough to orient. Sub-helps (`run/dev/alias/proxy/trust`) all present
  and accurate, except where noted in Phase 5.
- **`doctor` (cold, no daemon):** CA ✓ generated / ✗ not trusted (clear, points at
  `antra trust`) / ⚠ daemon not running (clear). **But:** reports
  `Port 443 (HTTPS) in use by another process` and same for port 80 **when nothing
  holds either port** (verified via `netstat`/`lsof`). Root cause: non-root
  `bind(443)` fails with `EACCES`, code treats any bind error as "in use".
  It then suggests `antra proxy start --port 8443 --http-port 8080` — right
  workaround, wrong diagnosis. Same misreport exists warm (see Phase 5).
- **Quick start:** `proxy start --port 8443 --http-port 18081` → daemon up in ~1s,
  both listeners verified via `lsof`. `alias` + `curl -sk` → 200 with correct body.
  A stranger who copies the website's `antra run --domain … -- pnpm dev` on the
  default ports will instead hit the silent-fallback path (see Phase 4).

## Issues filed from this run (ordered)

1. **`run --port X` / `dev` `port` silently remapped** (`src/util/port.rs:find_free_port_with_fallback` ignores any explicit port outside 4000–5000). Honor explicit ports verbatim; only auto-resolve on actual conflict, and always print the mapping reason.
2. **Leaf certs not chained to CA** (`src/certs/leaf.rs` never sets DN; subject CN stays `rcgen self signed cert`, no AKI). Set `distinguished_name` CN=hostname (and CA CN=`Antra Local CA`), add AKI/SKI so `openssl verify -CAfile ca.pem` passes and `trust` works.
3. **`doctor` conflates EACCES with EADDRINUSE** (`src/cli/doctor.rs:124-160`, `is_antra_daemon_port`). Distinguish permission-denied ("needs sudo / use fallback ports") from real conflicts (name the holder).
4. **`list` (and `open`/`remove`/`prune`) auto-start the daemon** (`src/cli/mod.rs:189-192,202-211,259-261`). Remove `ensure_daemon()` from read-only paths; keep for `alias`/`add` with a clear "starting daemon…" notice.
5. **HTTP→HTTPS redirect drops non-443 port** (`src/proxy/https.rs:run_http_redirect`). Preserve the actual HTTPS port in `Location`.
6. **`alias` overwrite + flag-name mismatch** — warn on existing-domain replace; make the public-domain error name a flag `alias` actually accepts (or add `--allow-custom-domain` to `alias`).
7. **Hosts-write `EACCES` is raw** (`myapp.internal` → `os error 13`). Wrap with "re-run with sudo" hint like the trust path has.
8. **First-run trust blocks non-TTY forever** (`src/cli/run.rs:maybe_prompt_trust`). Skip with a notice when stdin is not a TTY.
9. **Release gap**: repo is 0.2.1, install channel serves 0.1.0-era binary. Cut a release so strangers stop testing fixed bugs.
