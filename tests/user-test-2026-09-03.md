## Phase 1: Discovery (Website)

**What does this tool do?**
Antra gives local development apps real, stable HTTPS domains (like `myapp.localhost`) instead of `localhost:5173`. It acts as a local reverse proxy with automatic TLS certificates.

**What's the promise?**
One command gets you a real HTTPS URL for your local dev server. No ports, no /etc/hosts editing, no certificate warnings, transparent WebSocket/HMR support.

**Does the website make you want to try it?**
Yes. The problem section resonates — everyone's dealt with the `:5173` red lock and port confusion. The comparison table is convincing against ngrok and mkcert+Caddy. Built in Rust, no cloud/accounts/telemetry is a strong selling point.

**What's confusing or unclear?**
Nothing major. The architecture diagram is clean. I'd want to know what happens if my process dies — does the daemon keep running? What about Linux support? Only macOS seems mentioned via Homebrew.

**Questions before installing?**
Does it need sudo? What ports does it bind to (80, 443)? Will it conflict with my existing local servers? What if I already run something on port 80?

## Phase 4: Core Usage

**Setup:**
- Started `python3 -m http.server 9876` as test server
- Started antra daemon: `antra proxy start --port 8443 --http-port 8080`
- Created alias: `antra alias myapp.localhost 9876`

**Did it work on the first try?**
No. Several issues encountered:

1. **Daemon didn't stay alive:** After `antra proxy start`, the process immediately exited. `antra proxy status` said "Daemon is not running" right after starting. Required `antra clean` followed by restart to fix.

2. **Ports 80/443 need root:** The daemon silently failed to bind to privileged ports. `doctor` warned about it, but the error wasn't surfaced during `proxy start`. Had to use `--port 8443 --http-port 8080`.

3. **Auto-port detection failed:** `antra run --domain test.localhost -- python3 -m http.server 9877` (without `--port`) assigned a random port (51759) instead of detecting 9877. Got 503 errors. Had to specify `--port 9877` explicitly.

**Did you get a working HTTPS URL?**
Yes, but only on port 8443 (not standard 443). Access via `https://myapp.localhost:8443/` worked with a self-signed cert.

**How did the output feel?**
The CLI output is clean and well-formatted with checkmarks and arrows. The `antra list` table is clear. However, the silent daemon death and silent port binding failure are concerning.

## Summary

**The good:**
- Concept is excellent — solves a real pain point
- CLI output is clean and well-formatted
- Architecture is simple and understandable
- Fully local, no cloud dependency
- Multi-app routing works

**The bad:**
- Daemon silently dies after starting (requires `clean` + restart)
- Can't bind to ports 80/443 without root — no fallback messaging
- Auto-port detection in `antra run` doesn't work reliably
- `antra trust` needs sudo but doesn't suggest it
- `remove` silently succeeds on non-existent routes

**Critical fix needed:**
The daemon lifecycle is the #1 issue. If `proxy start` says "Daemon started", it should actually stay running. The current behavior destroys trust immediately.
