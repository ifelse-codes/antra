| 31 | Strict X.509 gate | **DONE** (v0.5.0) | Assert the rules a strict verifier enforces (no CA SAN, valid `dNSName` on leafs, serverAuth EKU, validity window) in `cargo test`, plus a macOS e2e that asks Apple's TLS stack via `/usr/bin/curl --cacert`. | Small | `src/certs/validate.rs`. |
| 32 | Daemon log file + `antra logs` | **DONE** (v0.6.0) | `antra proxy start` already redirects daemon output to `daemon.log`, but the *auto-started* daemon (spawned by `cli/mod.rs::ensure_daemon`) still gets `stdout/stderr → /dev/null`, so a failed HTTPS bind is invisible on the path most users take. Log there too, add `antra logs [-f]`, and have `doctor` tail the last errors. | Medium | `antra logs [-f] [--lines N]`; the auto-started daemon writes the same log `proxy start` did (it used to discard both streams); the launchd plist pointed at a *different* path, so service logs were unreachable. `doctor` tails the last errors. |
| 33 | Upstream connection reuse | **DONE** (v0.6.0) | One shared hyper client instead of one per request (`proxy/forward.rs:88`). | Medium | One pooled client in `ProxyState`; proved by `tests/upstream_pool.rs`, which counts upstream TCP connections (4 sequential requests → 1 connection, and the old per-request build → 4). |

| C10 | IPC socket perms: bind-then-chmod window | **DONE** (v0.6.1) | `platform::ensure_private_dir` creates the socket's parent chain at `0o700` *before* the bind, which closes both gaps at once: `connect(2)` needs execute permission on every path component, so a private directory makes the socket unreachable by another local user for its whole life rather than only after the `chmod` at `daemon/server.rs:253`. It chowns every component it creates to the invoking user, so `sudo antra proxy start` followed by an unprivileged `antra proxy status` still reaches the socket — a root-owned `0o700` chain would have locked the CLI out of its own daemon. | C12 | `e2e_all_features.sh` / `e2e_next_sprint.sh` not in CI | **NEXT** | Excluded from the C8 job for two reasons, one now fixed. **(a) SOLVED** — `e2e_all_features.sh` had 37 uncapped `antra dev` calls, and one whose dev command is a server (`python -m http.server`) hung the suite until the CI job's own timeout. All of them are capped now. **(b) OPEN** — the two detection suites assert on `antra dev`'s **spawn line** and on **registered routes**, neither of which is observable unless the referenced toolchain is actually installed. The rule that predicts it, verified against the suite: a test asserting only on *detection* is safe ungated (the Node framework tests pass on a lean runner), while a test asserting the chosen command or a route needs a `need` gate. The ungated tests that violate it, and the exact assertions observed failing on GitHub runners: `node_pnpm` (`pnpm run dev` — fails on **both** runners), `go_gin`/`go_echo`/`go_fiber`/`go_chi` (`go run`, `Default port 8080`), `ruby_rails` (`Rails server command used`, `Default port 3000 for Rails`), `ruby_sinatra` (`Default port 4567 for Sinatra`), `ruby_generic` (`Rackup command used`). Also `e2e_next_sprint.sh::test_service_status` fails on Linux, and this one is a **product bug, not a test-phrasing problem** — the test asserts the honest wording. `cli/service.rs:316-338` infers installed-vs-not from a single `systemctl --user is-active antra-proxy` code: `active` → running, `inactive` → "installed but not running" + `Run: systemctl --user start`, anything else → "not installed" + `Run: antra service install`. `is-active` does not reliably distinguish an absent unit file from a stopped one across systemd versions, and on the ubuntu runner it returns `inactive` for a service that was never installed. The user is then told to `systemctl --user start` something that does not exist, instead of `antra service install`. Distinguish the two properly — `is-enabled`, or the presence of the unit file — and keep the test as it is. |
