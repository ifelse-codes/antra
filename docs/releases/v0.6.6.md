One fix, the one every new macOS and Linux user hit first: the URL Antra printed had a port in it (C27). It landed on `main` on 2026-10-04 (#63) and was checked on a real Mac with a real `sudo` password prompt before release.

## C27 — a first run printed `:8443`, not the URL on the box

The README, the landing page and every example show:

```
antra run --domain myapp.localhost -- pnpm dev
→ https://myapp.localhost
```

On macOS and Linux only an admin can open port 443, so a first run without
`sudo` quietly fell back and printed `https://myapp.localhost:8443` instead.

The hint it printed to fix that was broken on Linux too: `sudo` there resets
`HOME` to root's, so `sudo antra proxy start` started a daemon whose files
sat under `/root`, and your own `antra proxy status` then said *Daemon is not
running*.

**Now:** the first time Antra starts its proxy in a terminal, it asks.

```
  Antra can give you https://<app>.localhost with no port number.
  Port 443 needs admin rights, so this asks for your password (sudo).
  The proxy drops admin rights as soon as the port is open, and stays
  up until you restart, so you are asked once.

  Use port 443? [Y/n]
```

- **Yes** (or Enter): `sudo` asks for your password once. The proxy opens
  ports 443 and 80, **then drops admin rights and runs as you**, with your own
  CA, socket and log. It stays up until you restart or run `antra proxy stop`,
  so you are not asked again. `antra proxy stop` needs no `sudo`.
- **No:** you get `https://myapp.localhost:8443`, as before.

Antra remembers either answer. To be asked again, delete the `use_port_443`
line from Antra's `config.toml` (`~/.config/antra/` on Linux,
`~/Library/Application Support/antra/` on macOS).

It never asks when there is no terminal (CI, scripts): a saved yes there runs
`sudo -n`, which fails instead of waiting for a password, and Antra falls
back to 8443. It also does not ask when something else already holds port
443, when you set `ANTRA_PORT` / `ANTRA_HTTP_PORT`, or when `sudo` is not
installed. Windows is unchanged.

**By hand** it is now `antra proxy stop && sudo antra proxy start`, and that
works on Linux too: under `sudo`, `antra proxy` finds your home and runtime
directory instead of root's. `sudo antra run` is unchanged — it still gets a
daemon that stays root, in root's paths.

The design and its guardrails are in `docs/security.md`, *Port 443 and
`sudo`*.

## Known gap: Linux Chromium and Firefox

Unchanged from v0.6.4. On Linux, `antra trust` installs the CA into the system
store, which `curl` uses — but **Chrome and Firefox read `~/.pki/nssdb`
directly**, so they still show `ERR_CERT_AUTHORITY_INVALID` /
`SEC_ERROR_UNKNOWN_ISSUER` after a successful trust.

**Workaround** (needs `libnss3-tools`):

```bash
sudo apt-get install -y libnss3-tools
certutil -d sql:$HOME/.pki/nssdb -A -t "C,," \
  -n "Antra Local CA" -i ~/.config/antra/ca.pem
```

## Checked

- **On a Mac, with a real `sudo` password prompt:** after the question and the
  password, `https://hello.localhost` opened with no port; `ps` on the
  daemon's pid printed the user's name, not `root`; a second `antra run` asked
  nothing and needed no password.
- **On Linux:** the exact command the first run hands `sudo`, replayed as root
  with the environment `sudo` leaves, from an empty `HOME`: the daemon held
  443 and 80 as the user (uid 1000, the user's own groups), the user's
  `antra run` printed `→ https://hello.localhost`, HTTPS answered 200 against
  the user's CA and port 80 answered `301 https://hello.localhost/`; then the
  user's `antra proxy stop`, without `sudo`, exited 0 and closed both ports.
- Ten new unit tests: five for when to ask, five for which paths to use
  under `sudo`. The code was broken on purpose three times and a test caught
  each one. Three bugs in the first version were fixed before merge — two
  found by replaying it (a log directory created as root; a socket fallback
  looked up under root's uid), one in review (`sudo antra run` handing the
  CLI and the daemon different homes).
- CI green on macOS, Linux and Windows, including the four shell e2e suites
  and the browser check.
