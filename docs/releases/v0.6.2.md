Two Linux fixes. No behaviour change on macOS or Windows.

## Fixes

**`antra service install` works on Linux.** It never did. Two separate problems:

- The systemd unit was written to `~/.config/antra/systemd/user/`, a folder `systemctl --user` does not search, so install always failed with `Unit file antra-proxy.service does not exist` — and then said the proxy would start on login anyway.
- Even in the right folder, systemd would have stopped the daemon a moment after starting it and restarted it every 5 seconds, because `antra proxy start` hands the daemon off to a background process and exits.

The unit now goes to `~/.config/systemd/user/antra-proxy.service` (or under `$XDG_CONFIG_HOME`), runs the daemon in the foreground, and writes its output where `antra logs` reads it. Install says *started* only once the daemon answers, leaves a working unit alone if a re-install fails, won't start a second daemon beside one that is already running (it tells you how to hand over), and says plainly when there is no systemd user session — common over SSH, in WSL and in containers. `ANTRA_PORT` / `ANTRA_HTTP_PORT`, if set when you run install, are written into the unit.

**The daemon starts on machines without IPv6.** Antra listens on both `127.0.0.1` and `::1`. Where IPv6 is switched off, the `::1` half always failed, and Antra reported it as `Both 443 and 8443 are in use` — on free ports — and refused to start. It now listens on `127.0.0.1` alone there, and only there. A port that is genuinely taken on `::1` is still refused, as before.

## Upgrading from v0.6.1 on Linux

If you ran `antra service install` on v0.6.1, it failed and left an unused file at `~/.config/antra/systemd/user/antra-proxy.service`. Run `antra service install` again: it installs the working unit and removes the old file. `antra service status` points this out.

## Known issue

On macOS, `antra service install` may relaunch `antra proxy start` every few seconds, writing "already running" into the daemon log. It is the macOS counterpart of the Linux problem above, found by reading the code and not yet confirmed on a Mac. `antra proxy start` without the service is unaffected.
