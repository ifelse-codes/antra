One macOS fix. No behaviour change on Linux or Windows.

## Fix

**`antra service install` on macOS keeps one daemon running.** In v0.6.2 and earlier, launchd started `antra proxy start` every ten seconds, for as long as the service was installed. Each run found the daemon already up, wrote "Daemon is already running" into the daemon log, and exited. Meanwhile the real daemon ran outside launchd's control: it would not have been restarted if it crashed, and `antra service uninstall` left it running.

The service now runs the daemon as launchd's own job. It starts once, launchd restarts it if it exits, and uninstall stops it. Install also:

- won't start a second daemon when one is already running — it tells you the one line to hand over instead
- says *started* only once the daemon actually answers
- carries `ANTRA_PORT` / `ANTRA_HTTP_PORT` into the service if you have them set
- escapes paths with characters like `&` in them, which would have produced a service file macOS could not read

## Upgrading from v0.6.2 or earlier on macOS

If you installed the service, run `antra service install` again. It will report that a daemon is already running — the one the old service left behind — and print the line to run:

```bash
antra proxy stop && launchctl load -w ~/Library/LaunchAgents/com.antra.proxy.plist
```

If you never ran `antra service install`, nothing changes for you.

## Checked on a real Mac

A GitHub macOS runner installed the service and watched launchd: v0.6.2 was started 7 times in a minute with no process supervised; this release is started once and launchd supervises the daemon for the whole watch. The same check covers installing beside a running daemon and upgrading over a v0.6.2 service, and it now runs on every change to the service code.
